Лёгкий драйвер DS18B20 AVR, без классов с прямым доступом к портам.

# Зачем?

Стандартная библиотека DallasTemperature удобная, но крайне тяжела, занимает 6.5~ кб flash. PopetDS18 делает то же самое за ~308 байт, потому что:

- работа напрямую с регистрами AVR, никакого DigitalWrite/pinMode
- нет класса и объектов - просто функции
- минимум функционала, только самое необходимое.

Плата за это:

- пины сменить можно только редактированием .h
- только AVR(Новые AVR Dx не поддерживаются)
- нельзя использовать несколько датчиков
- нельзя использовать EEPROM датчика
- нельзя использовать паразитное питание

Если гибкость важнее веса прошивки или нет нужных функций, то используй DallasTemperature, если у тебя условная ATtiny13 или крайне мало памяти и тебе всеравно на эти минусы, то вот для чего эта библиотека.

# Схема подключения

 	Изначально схема требует подключить пин датчика DQ к пину PD3(D3 на ардуино)
	Между DQ и VCC резистор 4.7 кОм (подтяжка, обязательна)

# Таблица функций

	uint8_t DS18_reset(void) // Инициализация датчика, также функция отдает 0 или 1 в зависимости от того ответил датчик на сброс или нет(если 1, то ответил)
	void DS18_WriteBit(uint8_t bit) // Записать бит
	void DS18_WriteByte(uint8_t Byte) // Записать байт
	uint8_t DS18_ReadBit(void) // Прочитать бит
	uint8_t DS18_ReadByte(void) // Прочитать байт
	void DS18getRaw() // Отправляет запрос на измерения температуры
	void DS18_SetResolution(uint8_t Resolution) // Задать разрешения 9 бит, 10 бит, 11 бит, 12 бит
	int16_t DS18getTemp(void) // Прочитать температуру датчика

# Быстрый старт в примере с PopetLCD

```
#include <PopetLCD.h>

#include <PopetDS18.h>

void setup() {
  LCD_init(); // инициализируем дисплей
  DS18_reset(); // инициализируем датчик
  DS18_SetResolution(12); // выставляем разрешения
}

void loop() {
  DS18getRaw(); // говорим датчику начать измерения
  _delay_ms(800);
  int16_t raw = DS18getTemp(); // читаем температуру
  uint8_t negative = 0;
  if (raw < 0) {
    negative = 1;
    raw = -raw;
  }
  int16_t whole = raw >> 4;
  uint8_t frac_units = raw & 0x0F;
  uint16_t centideg = whole * 100 + frac_units * 25 / 4;
  if (negative) LCD_data('-'); // если температура отрицательная то добавляем минус
  LCD_setCursor(0, 0);
  LCD_printInt(centideg); // выводим температуру
  _delay_ms(200);
}
```

Для сравнения: только перевод сырых данных в float и вывод через
Serial.print(float) добавляет ~1.85 КБ поверх этого - на AVR это дорогая операция, которой здесь можно избежать.
